# Build identity and support email

The **System** tab shows the source revision, branch, source fingerprint and
publication time. Publication time is recorded in UTC during web deployment and
displayed in the viewing device's timezone. A short revision identifies the last
Git checkpoint; the fingerprint also distinguishes local source changes.
`/assets/build-info.json` contains the full values. It is regenerated by
`tools/write_build_info.py`, not maintained by hand.

**Support email…** on that tab opens a local composer addressed to
`support@dejsoftware.com`. Describe the failure and choose **Collect diagnostics**.
This uses the shared on-demand caretaker password pop-up. Collecting a report
does not enable Debug or change any network/service setting.

The bounded snapshot includes build/publication identity, status and resources,
OS/kernel, hardware, storage/mounts, failed services and timers, network links,
addresses/routes, wireless assignment, forwarding policy, recent service and
kernel errors, application events, portal Debug logs, library progress and source
failures. Browser context includes its version, language, timezone, recent UI
errors, current page without private URL fragments/query strings, and last known
status. Missing telemetry is recorded rather than requiring every service to work.

Recent logs are bounded, not the entire log history. Debug must already have been
enabled to contain the corresponding capture. No household files, message bodies,
credential stores, environment dumps, passwords, keys or tokens are collected.
Recognized secrets in log records are redacted. The report can still contain
private technical details such as network names and addresses: review it before
sharing. It is not published on the public content drive.

**Download complete email (.eml)** creates a MIME email file with the JSON report
attached and the description/build context in the message. Open or import it in
your email client, review, and send. **Open email app** uses a conventional mail
link; those links cannot attach files, so attach the downloaded diagnostic JSON
yourself when using that route. Nothing is sent automatically. Without internet,
save the email/report and send later. If the API is unreachable, a clearly marked
partial report preserves browser/build context for the failure.

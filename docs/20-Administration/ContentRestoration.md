# Content configuration, shipping and restoration

## Two copies with different jobs

The authoritative public content configuration lives on the Pi's system drive under `/opt/dataark/config/content/`. The content SSD carries a readable mirror at `/mnt/storage/DATA-ARK-CONFIG/`. The repository provides the off-appliance copy on [GitHub](https://github.com/DavJenkins/pharos). [Browse the media-drive mirror](/library-files/DATA-ARK-CONFIG/index.html).

This separates desired content from the medium holding it. Replacing or emptying the SSD does not erase the system-drive selection. Moving the old SSD to another computer carries its source descriptions with it. Runtime download progress, partial files and update locks are not the authoritative selection.

The shell welcome remains on the system drive. Run `ark-help library` for the everyday starting points.

## What is recorded

- `config/content/content.yaml`: named archive selections, enabled flags, direct downloads, 174 installed map source recipes, the complete Windows reader folder inventory, collection recipes, dependencies, reserve space and a direct-download rate limit.
- `public-manifest.yaml`: public dashboard/catalogue, geography and map configuration. Private `bugout` settings are excluded. Existing appliance system/private settings are retained when applying a profile.
- `content-lock.json`: observed registration, installed state, file sizes and known SHA-256 hashes for 138 registered asset records. Absence is recorded rather than silently treated as an installed item.
- `snapshots/`: public source records, map source metadata, code-release provenance, callbook dates and pool provenance. These are descriptions, not copies of the books, databases or maps.
- `deploy/reference/*-catalogue.json`: human-readable individual forms, family-resource and resilience source lists with edition/license notes.
- `callsign-sources.json`: FCC bulk URL, Census ZIP-area source and edition.
- `radio-pools.json`: pinned transcription commit, pool editions, validity dates, counts, figures and withdrawn questions.
- `resilience-settings.json`: selected Massachusetts law chapters; `us-code-release.json`: pinned official U.S. Code source URL, release and hash.
- `osm-massachusetts.json`: regional extract bounds, source edition, maximum zoom and expected hash.

Generated paper packs are regenerated by their source program. Offline browser tools and their vendored dependencies live in the source repository; they are published by web deployment. They are not redownloaded as giant library payloads.

The intentionally removed Wikipedia-without-images archive is kept as `enabled: false`. Collection recipes restore their catalogues as groups: to omit an individual form/reference permanently, edit its source catalogue as well as reviewing the profile. This exporter is an explicit snapshot of managed content, not a background watcher of library-manager actions.

An older, unregistered `wikipedia_en_medicine_maxi_2026-01.zim` was discovered. It is reported as an unmanaged archive, not silently selected. Preserve it separately or add an explicit source recipe if it should be retained. Private bugout backups/drops, system-volume metadata and temporary download caches are outside this public recipe.

## Capture and mirror choices

After intentional library changes, capture the current installed selections and review the Git diff:

```sh
cd /opt/dataark
sudo /usr/bin/python3 tools/content_profile.py export
git diff -- config/content deploy/reference
```

Export writes the system-drive profile and its media-drive mirror. It refuses an unmounted or empty content drive; an empty inventory must not overwrite the saved desired library. To edit desired choices without rescanning current files, edit `config/content/content.yaml` and the referenced catalogues, then copy them to the SSD using:

```sh
sudo /usr/bin/python3 tools/content_profile.py mirror
```

Commit the reviewed public configuration files to the source repository. Neither export nor mirror pushes Git automatically. Refresh the snapshot after adding or removing content through older management interfaces; those interfaces do not yet maintain this profile automatically.

## Preview and rebuild

On an existing configured Ark with its content SSD mounted at `/mnt/storage`:

```sh
cd /opt/dataark
/usr/bin/python3 tools/content_profile.py plan
sudo /usr/bin/python3 tools/content_profile.py restore --apply
```

Without `--apply`, restore is a preview. No erase or format operation exists. Files download into staging paths, and known size/hash checks must pass before replacing an original. Existing matching-size files are skipped by default; add `--verify-existing` to read and hash existing files with recorded hashes. This can take a long time for hundreds of gigabytes. Unknown or failed sources are reported; a failure does not authorize accepting different content.

Resume by rerunning the command: verified files remain, direct downloads resume their staging file where the server permits it, and collection installers retain their own verification behavior. Direct archive/map writes coordinate with existing worker locks; parallel restore commands are rejected. Final results are saved to `config/content/last-restore.json`; an unsuccessful run exits with an error. Collection installers may record unavailable individual publishers while completing the rest, so review their `sources.json` records as well as the top-level report.

Select a subset with repeatable options:

```sh
/usr/bin/python3 tools/content_profile.py plan --only archives
sudo /usr/bin/python3 tools/content_profile.py restore --apply --only forms
sudo /usr/bin/python3 tools/content_profile.py restore --apply --only family
sudo /usr/bin/python3 tools/content_profile.py restore --apply --only indexes
```

Family resources automatically include their forms dependency. A complete restore orders archives, preparedness/map files, portable Windows reader, OSM, forms, family resources, resilience/legal references, callsigns, radio study and indexes. The index step publishes the dashboard/docs and restarts the existing Kiwix container so it sees restored archives. It does not install or reconfigure the Kiwix service itself. A partial restore may need `--only indexes` afterwards.

The `reserve_gib` setting protects free space for direct downloads. `download_rate_kib: 0` means unlimited for those downloads; a positive integer limits curl downloads. Existing collection installers retain their own bounded workers and size caps and do not currently inherit that rate limit. Regional OSM extraction requires the documented `pmtiles` CLI. The application Python environment, system Python/PyYAML/ReportLab/Pillow, curl, ZIP tools and Poppler must already be installed as documented by the existing Ark setup.

## Ship a small configuration bundle

```sh
/usr/bin/python3 tools/content_profile.py bundle --output /tmp/dataark-content-config.tar.gz
```

The archive contains only the allowlisted public YAML/JSON profile, source snapshots and referenced content configuration files. It excludes library payloads, passwords, network credentials, private backup directories and unrelated observed machine-configuration files. Keep it with a copy of the matching source repository. Extract the bundle into that repository to put `config/content` and `deploy/reference` back in place, preview the plan, then explicitly restore.

This is content restoration for a prepared Ark, not yet a tested bare-Pi-image bootstrap. A replacement SSD must be formatted and mounted by the existing appliance setup; this command does not choose, format or mount a disk. Rebuild-on-boot is a possible separate policy, not enabled by this change. If added, it should read the system-drive desired profile, wait for the actual content mount and internet, retain selections, and expose progress/failures rather than blocking the local library indefinitely.

## What configuration alone cannot guarantee

Pinned URLs can disappear. FCC complete files are rolling snapshots; without the preserved source ZIP a later restore imports a later callbook. Some publisher documents change at stable URLs. Rebuilt HTML includes new retrieval metadata and is not byte-identical to the original capture. Exact map extraction may depend on the recorded source and extractor behavior. Missing copyrighted code books and publisher-blocked documents remain gaps, not magically restored content.

For guaranteed recovery without publishers or internet, retain an independent content mirror (including source ZIPs and licensing notices), plus a protected appliance-configuration backup. The readable content profile describes what to restore; it is not a substitute for those bytes or for a hardware/OS recovery image.

## Verification

The complete profile was exported and dry-run planned without deleting content. Tests cover traversal and credential-bearing URL rejection, disabled selections, dependency ordering, unknown selections, checksum failure preserving an existing file, successful staged replacement and the bundle allowlist. A small real publisher file is restored into an isolated test directory as an integration check. A full empty-SSD rebuild of the hundreds-of-gigabytes collection has not been performed; that remains an acceptance test before promising unattended disaster recovery.

Other Ark resources

The Ark’s main job is to preserve and serve useful content, especially under adverse conditions. The computer, network, storage and tools it brings along can also help with other tasks.

These capabilities are available alongside the library. Access requirements differ; reading and copying public content remain open to everyone.

Local network

The DataArk hotspot serves the library and local browser tools without internet. Internet pass-through is available only when the Ark has a working upstream connection.

Connection and pass-through guide

Files and storage

Copy public files through HTTP, read-only SMB or anonymous FTP. Authorized accounts can use SFTP and rsync. The SSD can be used on another compatible computer after a clean shutdown.

File access methods

A Linux computer and tools

With Linux login authorization, use the terminal for calculations, scripting, editing and local data work. Python 3, Git, archive utilities, nano, GCC and make are installed. Additional libraries or hardware may be needed for a particular task.

Open Settings → System → Terminal. It requires the Linux admin password and first-use HTTPS certificate review.

Existing remote access

Checked October 23, 2026: AnyDesk is installed and running. The RDP desktop service (xrdp) is running on port 3389. SSH provides remote shell and file transfer on port 22.

Desktop logins and AnyDesk’s offline connection path have not been verified. VNC is available on port 5901 with encrypted Linux login. Windows RealVNC desktop access was confirmed over both the home LAN and DataArk hotspot. Classic rsh is not installed; legacy compatibility remains a possible fallback.

System status, local help, the Developer API and the Ark’s source code can help investigate faults or adapt the appliance without a cloud connection.

Possibilities, not installed services

Local coordination apps, shared workspaces, printing, sensing and equipment interfaces could make use of this platform. They require their own configuration, dependencies and testing; this page does not enable them.

Keep the library available

Peripheral use should preserve content access. Avoid exhausting storage, memory, power or network capacity. Keep private work off public shares. Shell access and changes to shared state require authorization because they can affect everyone.
